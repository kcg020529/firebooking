# Firebooking 보안 아키텍처 발표

외부 서버나 API 없이 실행되는 발표용 스크롤 페이지입니다. `presentation/index.html`을 브라우저로 바로 열면 됩니다. 파일 경로 제약이 있으면 프로젝트 루트에서 `npx serve presentation`을 실행한 뒤 표시된 주소를 엽니다.

본문 글꼴 Pretendard는 CDN에서 불러옵니다. 발표장 인터넷이 끊겨도 Malgun Gothic으로 대체되어 내용은 그대로 보입니다.

## 발표 조작

한 번 스크롤할 때마다 흐름도의 `DATA` 표시가 다음 처리 노드로 한 구간 이동합니다. 오른쪽 아래 카드의 `입력`은 그 단계로 들어오는 값, `처리`는 서버가 하는 검사·저장, `결과`는 다음 단계로 넘어가거나 기록되는 값입니다. 사진이 여러 장인 장면은 단계에 맞춰 왼쪽 화면이 바뀝니다.

방향키 위/아래·좌/우, Page Up/Page Down으로 한 단계씩 이동합니다. Home은 첫 단계, End는 마지막 단계입니다. Chromium 계열 브라우저 전체 화면, 1920×1080 해상도를 권장합니다.

## 장면과 스크린샷

스크린샷은 `presentation/src/`에 있고, 사진 번호 N이 장면 N+1에 쓰입니다. 장면 01(개요)은 사진 없이 소개 패널을 보여줍니다. 어떤 단계에서 어떤 사진을 쓸지는 `scenes.js`의 각 단계 `screenshot` 값으로 정합니다.

| 장면 | 내용 | 사진 |
| --- | --- | --- |
| 01 | 프로젝트 개요 | 없음 |
| 02 | 챗봇 예약 → 예약 조회 | `1_1` ~ `1_4` |
| 03 | 수동 예약 → 예약 조회 | `2_1` ~ `2_3` |
| 04 | 프롬프트 인젝션 차단 · Discord 알림 · 감사 로그 | `3_1` ~ `3_3` |
| 05 | 예약번호 열거 탐지 | `4_1` ~ `4_2` |
| 06 | 운영 메트릭 대시보드 | `5_1` ~ `5_2` |
| 07 | Critical IP 조사 | `6_1` ~ `6_2`, 앞 세 단계는 `4_2` |

사진 파일을 읽지 못하면 그 자리에 안내 문구가 나오고, 흐름도와 설명은 그대로 동작합니다.
