# 보안 탐지·대응 대시보드 설계

## 목표

보안 이벤트를 공격/비공격으로 명확히 분류하고, 반복 공격 IP를 애플리케이션과 Cloudflare에서 함께 차단한다. 관리자는 차단과 로그인 잠금을 해제할 수 있으며, 대시보드에서 서버 상태와 공격 추이를 즉시 확인한다.

## 탐지와 심각도

- 규칙 메타데이터를 `lib/security/securityConfig.js`의 단일 원본으로 관리한다.
- 각 규칙은 한글 이름, 공격 여부, 심각도, 판정 기준과 대응 설명을 가진다.
- 상(`critical`)은 즉시 대응이 필요한 침해·반복 공격, 중(`warn`)은 차단된 의심 행위, 하(`info`)는 정책상 확인할 이벤트로 제한한다.
- 주민번호와 카드번호 입력란이 없으므로 `PII_RRN`, `PII_CARD` 규칙은 제거한다.

## IP 차단

- `ip_blocklist`에는 원본 IP가 아니라 IP 해시, 출처 이벤트, 차단 상태, Cloudflare 규칙 ID와 감사용 메타데이터만 저장한다.
- 관리자가 critical 이벤트의 보관된 IP를 근거로 차단할 수 있다.
- 동일 IP의 관리자 영역 비인가 접근이 10분 내 3회이면 자동 차단한다.
- 로그인 API는 활성 블랙리스트를 먼저 확인해 `운영자에 의해 차단되었습니다.`를 반환한다.
- Cloudflare API 동기화가 성공하면 이후 요청은 서비스에 도달하기 전에 차단된다.
- 차단 해제는 Cloudflare 규칙 삭제가 성공한 뒤 DB 상태를 비활성화한다. 실패 시 차단을 유지하고 오류를 표시한다.

## 로그인 대응과 회원가입

- 로그인 잠금 이벤트에는 원문 이메일/IP 대신 기존 HMAC 제한 키를 대응 대상으로 연결한다.
- 관리자는 해당 이벤트에서 15분 잠금을 즉시 해제할 수 있다.
- 회원가입은 서버 API를 단일 진입점으로 사용하고 `@` 뒤 도메인에 점이 있는 이메일만 허용한다.

## 대시보드

- 보안 이벤트에 공격/비공격 필터와 읽을 수 있는 한글 규칙 이름을 제공한다.
- 규칙별 막대와 시간대별 공격 추이에 심각도 색을 사용한다.
- `/api/health`를 주기적으로 호출해 앱, DB, 마지막 확인 시각과 응답 지연을 표시한다.
- 차단 목록에서 활성 상태, Cloudflare 동기화 상태와 해제 기능을 제공한다.

## 데이터와 오류 처리

- 새 테이블은 RLS를 켜고 브라우저 직접 접근을 허용하지 않는다.
- Cloudflare 토큰과 Zone ID는 서버 환경변수만 사용한다.
- 외부 API 실패를 성공으로 표시하지 않는다. 차단 생성 실패는 앱 차단을 유지하고, 해제 실패는 기존 차단을 유지한다.
- 실제 Supabase에는 적용하지 않고 재현 가능한 마이그레이션 SQL만 추가한다.
