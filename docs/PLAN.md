### Tier 1 — 값싼 확장 (Day 9 오전, 각자 2시간 타임박스)

| 항목 | 비고 |

| 알림 체계 | critical 발생 시 대시보드 배너 |

### Tier 2 — 여유 있으면 (Day 9 오후)

예약 취소 · Discord/Slack 웹훅 · 대시보드 차트

> 2주판이 죽는 방식은 하나다 — **대시보드를 먼저 예쁘게 만들어 놓고 탐지할 로그가 없는 상태로 발표일을 맞는 것.**

- **오전** — GitHub 저장소 + 3명 초대(완료), `npx create-next-app@latest`(JS · Tailwind · App Router), Vercel 연결, **첫 배포 확인**
- **오전** — Supabase 프로젝트 + Auth 켜기, DeepSeek 키 발급 + 크레딧 충전
- **오후** — A가 **8개 테이블 + RLS 정책** 실행. `withApiLog()` 래퍼로 `api_logs`에 행이 쌓이는 것까지 확인
- **오후** — [docs/DECISIONS.md](DECISIONS.md) 2번 표를 다 채운다. 보안 4축 담당 확정

> **GATE — Day 1 저녁**

- **B** — 디자인 톤 + 공통 컴포넌트 + 홈·상세 (mock 데이터)

### Day 4–5 (목·금) — 병렬 후반

- **C** — tool 3개 + 시스템 프롬프트 + `injection.js`. **공격 시나리오 10종 작성 시작**

> **GATE — Day 5 저녁**

### Day 6 (월) — 통합 1일차, A가 지휘

- **오후** — C가 tool을 `lib/bookings.js`에 배선, 대시보드를 실제 `security_events`에 연결

### Day 7 (화) — 예약 + 감사 흐름 관통

- 로그인 → 예약 → 예약번호 → `/my` 조회 → `audit_logs`·`api_logs`에 기록 확인

### Day 8 (수) — 챗봇 + LLM 보안 관통 · 가장 위험한 하루

  **단 PII 마스킹과 인젝션 탐지는 남긴다** (과제의 본체이므로)

> **GATE — Day 8 저녁 · Tier 0 완성, 갈림길**

## 완성 판정 체크리스트

Day 5 · Day 8 · Day 9 저녁에, 로컬이 아니라 **배포된 URL에서** 돌려본다.

- [ ] **예약 폼** 홈 → 골프장 → 시간 → 입력 → 예약번호. DB에 `source='form'`
- [ ] **예약 챗봇** 대화로 완료, 버튼만 눌러서도 완료. DB에 `source='chat'`
- [ ] **S1** `chat_logs`에 전화번호가 마스킹돼 저장되고 원문이 어디에도 없다
- [ ] **S1 오탐** "스크린골프 예약할게요"가 이름으로 오탐되지 않는다
- [ ] **S2** 인젝션 문장이 LLM 호출 전에 차단되고 critical 이벤트가 남는다
- [ ] **S2** 존재하지 않는 예약번호 5회 조회 시 `ANO_CODE_ENUM` 발생
- [ ] **S3** 모든 `/api/*` 호출이 `api_logs`에 남고 응답시간이 기록된다
- [ ] **S3** 배포 사이트 F12 → Sources/Network에서 `sk-ant`·`service_role` 검색 결과 0건
- [ ] **S4** 일반 계정의 `/admin` 접근이 차단되고 감사 로그에 `result='deny'`로 남는다
- [ ] **S4 RLS** anon 키로 `security_events`를 직접 조회하면 **DB가 거절한다**
- [ ] **대시보드** 이벤트가 심각도 색으로 구분되고, 발생 직후 새로고침하면 보인다
- [ ] **모바일** 폰 브라우저에서 예약 2경로가 된다

## 리스크

| 리스크 | 대응 |
|---|---|
| **대시보드를 먼저 만든다** — 최대 위험 | 탐지할 로그가 없으면 대시보드는 빈 표다. Day 1에 `api_logs`부터 쌓는 이유 |
| 보안 반 + 예약 반 = 실제로 빡세다 | Tier 0에 보안 4축을 최소 형태로만 넣었다. **넓게 얕게가 이 과제엔 맞다** — 중점 역량 4개를 다 건드려야 하므로 |
| PII 이름 탐지 오탐 폭발 | 문맥 정규식으로 좁히고, **오탐 사례와 튜닝 과정을 발표 자료로 전환** |
| 인젝션 탐지가 정규식이라 우회 가능 | 사실이고, **한계로 명시하는 게 정직한 발표다** |
| Day 1 세팅이 하루를 넘긴다 | 셋이 같은 자리에서 한 화면 보며 진행. 각자 집에서 하면 이틀 간다 |
| 세 사람의 AI가 서로 다른 코드를 짜준다 | [CLAUDE.md](../CLAUDE.md)에 계약·스키마·규칙 ID를 넣어 같은 문서를 읽게 한다 |
| 발표 당일 챗봇 헛소리 | 시연 3단계로 넘어가 기존 로그로 진행. 캡처 스크린샷 백업 |
